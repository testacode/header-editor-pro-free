HTTP ヘッダーの編集、リクエストのリダイレクト、Cookie の追加 — 環境ごとにプロファイルを

Chrome と Firefox 向けの無料・オープンソースの拡張機能。ステージングでのテスト、認証や CORS のデバッグ、環境の切り替えをコードに触れずに行えます。

できること

リクエストヘッダーとレスポンスヘッダー

任意のヘッダーを設定・追加・削除。それぞれにスイッチとメモ欄があり、半年後でもそのトークンがなぜあるのかがわかります。

環境間のリダイレクト

正規表現に一致するリクエストを別の URL（ステージングやローカルサーバー）へ。$1 キャプチャグループに対応し、転送先が別オリジンなら CORS をオンにできます。

プロファイルごとの Cookie

ブラウザに保存せずに、ドメインへのリクエストに Cookie を追加。一時停止やプロファイル切り替えですぐに止まり、同名の Cookie をサイトが既に持っている場合は警告が出ます。

そのほか

プロファイルとフィルター

プロファイルは無制限。それぞれを特定のドメイン、または Chrome ではタブグループに限定できます。

インポートとエクスポート

JSON バックアップ、他のヘッダーエディタのプロファイル一覧、Requestly のリダイレクトルール。

有効な設定を共有

プロファイルで有効な項目をコピー。チームメイトはそのまま使えるプロファイルとしてインポートできます。

一時停止

ワンクリックですべてのルールをオフに。設定は失われません。

設定か追加か

Accept や Cookie など複数値のヘッダーは、置き換えずに値を追加できます。

よくある使い方

  • 認証付きエンドポイントを呼ぶAuthorization: Bearer <token>
  • フロントエンドをステージングに向けるapi.example.com → staging-api.example.com
  • CORS をデバッグするAccess-Control-Allow-Origin: *
  • 機能フラグや A/B バリアントを強制するCookie: ab_variant=B

データはブラウザの中だけに

プロファイルはローカルに保存されます。サーバーも分析もアカウントもなく、ルールはブラウザ自体が適用するため、拡張機能が変更対象のリクエストを見ることはありません。コードは GitHub で確認できます。
