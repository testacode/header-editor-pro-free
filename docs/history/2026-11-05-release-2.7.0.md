# 2.7.0 — redirects, cookies, Requestly import (2026-11-05)

What changed, why each decision went the way it did, and what is still open.
The code and `CLAUDE.md` say *what* exists; this file keeps the *why*.

## In one paragraph

A feature comparison against an internal header tool showed what we were
missing: URL redirects, cookies, Requestly import, notes, sharing and a light
theme. Before adding new rule types, the state machines were audited and two
problems fixed first (non-atomic rule swap, dead flags). Rule generation was
then extracted into a pure compiler, and every feature after that is a new rule
type in it plus a popup module. Each user-visible feature was verified in a real
Chrome through a new playground, which is now the end-to-end check for every PR.

## Decisions and their reasons

**Redirects, cookies and everything else live per profile, not globally.**
They inherit pause, domain filter, tab group scoping and export for free. A
Requestly "group" maps to one of our profiles.

**Users write `$1`; the compiler emits `\1`.** DNR's `regexSubstitution` only
understands `\1`. `$1` is what people know from Requestly.

**Every redirect pattern is wrapped in `^.*?(?:…).*$`.** DNR replaces only the
matched part of the URL, so an unanchored pattern produced
`https://https://…`. Found while researching the Requestly format, not by our
own e2e test, which happened to use an anchored pattern. Matching is also
case-sensitive (`(?i)` opts out), because DNR's default is the opposite.

**Redirects skip navigations** (`main_frame`, `sub_frame`), like the tool we
compared against: a bad pattern can't hijack the page you are on.

**CORS on a redirect is opt-in and sets `*`.** Without it a cross-origin
redirect is blocked by the browser even though the rule worked. `*` does not
work for credentialed requests, and DNR cannot echo the request's `Origin`, so
it is documented rather than solved. It runs at the lowest priority
(`PRIORITY.cors`), so a header the user sets explicitly always wins.

**Managed cookies go through the `Cookie` request header, not the cookie jar.**
That way they obey pause, profiles, filters and tab groups with no extra
state machine, and need no cleanup. The trade-off, verified in Chrome: a site
cookie with the same name is sent first and usually wins, and DNR can't replace
a single cookie. Hence the ⚠ that offers to delete the site's own cookie. The
`cookies` permission is only for that and for the site cookie viewer.

**Requestly rules with filters (method, resource type, page…) are skipped,
and the user is told which ones.** Importing them without their filters would
redirect more than the original rule did. The user chose skip-and-report over
import-broader.

**Naming Requestly is fine; naming the other tool is not.** An earlier commit
removed a competitor's name from everything public because that tool was pulled
from the stores for a security problem. Requestly has no such history, and the
name is what people search for when migrating.

**Light theme: dark stays the default and pixel-identical.** Each original grey
became its own CSS variable rather than being merged into a palette, so nothing
changed for anyone who never switches. The choice lives in `localStorage`, read
synchronously before the first paint, so the popup never flashes dark.

**One release for everything** instead of one per feature, at the user's request.

## How it was verified

- Unit tests: from 416 to 552 across the work.
- `npm run playground -- --check` (Chrome for Testing): headers, response
  headers, redirect with CORS off and on, navigation not redirected, managed
  cookie with and without a same-name site cookie, share active items, theme
  toggle with screenshots. About 4 seconds per run.
- AMO linter: 0 errors.
- Not verified by us: Firefox at runtime. AMO's validation passed; a person
  is testing the published build.

## Process notes that outlived the release

- `CLAUDE.md` no longer carries a test count: it changed in every PR and was
  the cause of almost every merge conflict.
- Branches are deleted on merge (repository setting).
- No Claude attribution in commits or PRs (global rule).

## Still open

- Firefox runtime behaviour of redirects, cookies and the theme.
- The manifest's short description (`appDesc`, 7 languages) doesn't mention the
  new features; changing it needs another release.
- Store screenshots predate redirects and cookies.
